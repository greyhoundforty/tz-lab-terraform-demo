90-minute lab

Power Virtual Server session

The VPC and the Ubuntu server already exist. Each student starts in IBM Cloud Shell, then SSHes to that server. Terraform creates the PowerVS workspace, the PowerVS SSH key, the transit gateway, and the AIX server. It does not create a VPC.

IBM Cloud CLI Terraform Ansible AIX

How the 90 minutes split

Cloud Shell 15 min
SSH 5 min
Workspace and gateway 30 min
AIX server 25 min
Confirm 15 min

Session order

  1. 0–15 15 min
    1

    Prepare Cloud Shell

    IBM Cloud CLI

    Log in to the IBM Cloud portal and open Cloud Shell. Create an RSA key and an API key, install the PowerVS plugin, and read the existing VPC and virtual server.

    Run

    ssh-keygen -t rsa -b 4096 -f ~/.ssh/pvs-lab -N ""
ibmcloud iam api-key-create pvs-lab -d "PowerVS lab" --file ./pvs-lab-apikey.json
ibmcloud plugin install power-iaas -f
ibmcloud is vpcs
ibmcloud is instances

    Expect

    ~/.ssh/pvs-lab.pub starts with ssh-rsa. The API key file contains apikey. power-iaas is in ibmcloud plugin list. ibmcloud is vpcs shows the VPC name for vpc_name. ibmcloud is instances shows the Ubuntu server and its floating IP.

  2. 15–20 5 min
    2

    SSH to the existing server

    IBM Cloud CLI

    The server already authorizes the Cloud Shell public key. Terraform, Ansible, the IBM Cloud CLI, the PowerVS plugin, and this repo are already installed.

    Run

    scp -i ~/.ssh/pvs-lab ./pvs-lab-apikey.json ubuntu@<floating-ip>:
ssh -i ~/.ssh/pvs-lab ubuntu@<floating-ip>
terraform version
ibmcloud plugin list
ls lab/terraform

    Expect

    The login user is ubuntu. Terraform and power-iaas are present. lab/terraform is the stack to apply.

  3. 20–50 30 min
    3

    Create the workspace, SSH key, and transit gateway

    Terraform

    First plan and apply. aix_image_name stays empty, so the AIX server stays out of this plan. Terraform reads the existing VPC and does not create one. Read workspace.tf and gateway.tf while the workspace comes up.

    Run

    export IC_API_KEY="$(jq -r .apikey ~/pvs-lab-apikey.json)"
cd lab/terraform
cp terraform.tfvars.example terraform.tfvars
# set vpc_name and ssh_public_key; leave aix_image_name empty

terraform init
terraform plan
terraform apply

    Expect

    The plan adds the PowerVS workspace, private network, PowerVS SSH key, transit gateway, both connections, and a delegate route on the existing VPC. Apply prints workspace_crn.

  4. 50–75 25 min
    4

    Create the AIX virtual server

    IBM Cloud CLI Terraform

    Target the new workspace, copy an AIX image name, and apply again. Read instance.tf while the server provisions.

    Run

    ibmcloud login --apikey "$IC_API_KEY" -r us-south
ibmcloud pi workspace target "<workspace_crn>"
ibmcloud pi image list-catalog

# lab/terraform/terraform.tfvars
aix_image_name = "<name from image list-catalog>"

terraform plan
terraform apply

    Expect

    The catalog lists stock images. The plan adds the image copy and the AIX server. The workspace, SSH key, and transit gateway stay in place. ibmcloud pi ssh-key list shows the key Terraform imported.

  5. 75–90 15 min
    5

    Confirm the workspace and the server

    IBM Cloud CLI

    The PowerVS plugin is still targeted at the workspace from the previous step.

    Run

    ibmcloud pi workspace context
ibmcloud pi instance list
ibmcloud pi ssh-key list

    Expect

    The context CRN matches workspace_crn. The instance list shows the AIX server. The SSH key list shows the key created from the Cloud Shell public key.

Destroy stays after class. PowerVS teardown is too slow to spend the session on.
