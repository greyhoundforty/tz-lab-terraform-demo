90-minute lab

Power Virtual Server session

The VPC and the Ubuntu server already exist. Guacamole is already running on that server. Each student opens it in a browser and lands in a shell as ubuntu. From that shell they create the PowerVS SSH key and apply Terraform, which reads the existing VPC and creates the workspace, the PowerVS SSH key, the transit gateway, and the AIX server.

IBM Cloud CLI Terraform Ansible AIX

How the 90 minutes split

Browser session 10 min
API key and SSH key 10 min
Workspace and gateway 30 min
AIX server 25 min
Confirm 15 min

Session order

  1. 0–10 10 min
    1

    Open the server in the browser

    Guacamole

    Log in to the IBM Cloud portal only to confirm the account. The shell is Guacamole, already running on the Ubuntu server. Open the lab URL, sign in as student with password pvs-lab, and choose the connection named Lab server.

    Open

    http://<floating-ip>:8080/guacamole/
    ubuntu@demoguac 
    whoami
terraform version
ibmcloud plugin list
ls ~/tz-lab-terraform-demo/lab/terraform

    Expect

    The prompt is ubuntu. Terraform, the IBM Cloud CLI, and power-iaas are already installed. The demo repo is already cloned.

    In nano or vi, click Ctrl in the lower right of the Guacamole screen to send a control key. Click it again so it is unselected before Enter, and before the keystrokes that leave the editor. A selected Ctrl stays down for the next key.

  2. 10–20 10 min
    2

    Create the API key and the PowerVS SSH key

    IBM Cloud CLI

    In the portal, open Manage, then Access (IAM), then API keys, and create a key. Paste it into this shell. The RSA key created here is the PowerVS key Terraform will import. It is separate from the key Guacamole already uses to reach this server.

    ubuntu@demoguac 
    export IC_API_KEY="<paste the API key>"
ssh-keygen -t rsa -b 4096 -f ~/.ssh/pvs-lab -N ""
ibmcloud login --apikey "$IC_API_KEY" -r us-south
ibmcloud is vpcs
cat ~/.ssh/pvs-lab.pub

    Expect

    Login succeeds for the lab account. ibmcloud is vpcs prints the VPC name for vpc_name. The public key starts with ssh-rsa. Keep this shell open so IC_API_KEY stays set.

  3. 20–50 30 min
    3

    Create the workspace, SSH key, and transit gateway

    Terraform

    First plan and apply, still in the Guacamole shell. aix_image_name stays empty, so the AIX server stays out of this plan. Terraform reads the existing VPC. Read workspace.tf and gateway.tf while the workspace comes up. If you edit terraform.tfvars in nano or vi, use the on-screen Ctrl button and turn it off before Enter and before leaving the editor.

    ubuntu@demoguac 
    cd ~/tz-lab-terraform-demo/lab/terraform
cp terraform.tfvars.example terraform.tfvars
# set vpc_name from ibmcloud is vpcs
# set ssh_public_key to the ssh-rsa line from cat ~/.ssh/pvs-lab.pub
# leave aix_image_name empty

terraform init
terraform plan -out default.tfplan
terraform apply default.tfplan

    Expect

    The plan adds the PowerVS workspace, private network, PowerVS SSH key, transit gateway, both connections, and a delegate route on the existing VPC. Apply prints workspace_crn.

  4. 50–75 25 min
    4

    Create the AIX virtual server

    IBM Cloud CLI Terraform

    Target the new workspace, copy an AIX image name, and apply again. Read instance.tf while the server provisions.

    ubuntu@demoguac 
    ibmcloud login --apikey "$IC_API_KEY" -r us-south
# still in ~/tz-lab-terraform-demo/lab/terraform
ibmcloud pi workspace target $(terraform output --raw workspace_crn)
ibmcloud pi image list-catalog

# lab/terraform/terraform.tfvars
aix_image_name = "<name from image list-catalog>"

terraform plan -out default.tfplan
terraform apply default.tfplan
terraform output -raw aix_ip_address

    Expect

    The catalog lists stock images. The plan adds the image copy and the AIX server on system type s122. Apply adds a route on this server for the PowerVS CIDR through the subnet gateway, and prints aix_ip_address.

  5. 75–90 15 min
    5

    Confirm the workspace and the server

    IBM Cloud CLI

    Stay in ~/tz-lab-terraform-demo/lab/terraform. Ping the AIX address, then SSH in as root with the PowerVS key created on this server. The first connection asks you to trust the host key. Answer yes.

    ubuntu@demoguac 
    ibmcloud pi workspace context
ibmcloud pi instance list
ibmcloud pi ssh-key list

aix_ip=$(terraform output -raw aix_ip_address)
ping -c3 -q "$aix_ip"
ssh -i ~/.ssh/pvs-lab root@"$aix_ip"

    Expect

    The context CRN matches workspace_crn. The instance list shows the AIX server. The SSH key list shows the key created in this shell. Ping reports 3 packets transmitted and 3 received. SSH prints Welcome to AIX Version 7.3! and the prompt is root.

Destroy stays after class. PowerVS teardown is too slow to spend the session on.
