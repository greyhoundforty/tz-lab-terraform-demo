Power Virtual Server session

90 min

Students use Cloud Shell or a terminal on their workstation, create the PowerVS key, and apply Terraform. They SSH to the AIX server on its public address.

Each student opens IBM Cloud Shell from the portal, or the terminal built into their workstation. From that shell they create the PowerVS SSH key and apply Terraform, which reads ~/.ssh/pvs-lab.pub. The first apply creates the workspace, a private network, a public network, and the SSH key. The second apply creates the AIX server on both networks. SSH, ping, and Ansible use aix_public_ip. Leave vpc_name empty unless this apply is attaching an existing VPC. When it is set, Terraform also creates the transit gateway and a delegate route.

How this page works

  • Copy puts one command block on your clipboard. Grey # comments sit above each command and are left out.
  • Terraform reads the PowerVS public key from ~/.ssh/pvs-lab.pub. You do not paste it into terraform.tfvars.
  • Save the plan with terraform plan -out default.tfplan, then apply that file.
  • Leave vpc_name empty unless this apply is attaching an existing VPC.
  • SSH, ping, and Ansible use aix_public_ip. Cloud Shell and a workstation can reach that address.

What you build today

  • A PowerVS workspace, a private network, and a public network
  • A PowerVS SSH key imported from ~/.ssh/pvs-lab.pub
  • An AIX virtual server on system type s122, on the second apply, with a public address for SSH
  • An Ansible check that reads oslevel and pings back from AIX
  • When vpc_name is set, a transit gateway and a delegate route into that VPC

Session order

1

Open Cloud Shell or your workstation terminal

0–10 · 10 min
IBM Cloud CLI

In the IBM Cloud portal, open Cloud Shell from the menu. Or open the terminal on your workstation. Run the rest of the lab in that shell. Clone the repo if it is not already on this machine.

cloud shell or workstation 
# confirm Terraform is installed
terraform version
# confirm the CLI is installed
ibmcloud version
# where this repo will live
repo=~/tz-lab-terraform-demo
# skip the clone if it is already here
test -d "$repo" || git clone https://github.com/greyhoundforty/tz-lab-terraform-demo.git "$repo"
# the directory you apply from
ls "$repo/lab/terraform"
Expect
Terraform and the IBM Cloud CLI print a version. The lab directory is on this machine.
Overview
Cloud Shell
The browser terminal in the IBM Cloud portal. Open it from the menu, or use the terminal on your workstation. Either shell is where the rest of this lab runs, so keep the same one open.
IBM Cloud CLI
ibmcloud is the command-line client for the account. ibmcloud version prints the client version when it is installed. Commands for a service, including PowerVS, come from a plugin.
Terraform
The tool that creates the workspace, both networks, the key, and the AIX server from lab/terraform/. terraform version confirms it is installed before you clone the repo.
2

Create the API key and the PowerVS SSH key

10–20 · 10 min
IBM Cloud CLI

In the portal, open Manage, then Access (IAM), then API keys, and create a key. Paste it into this shell. The RSA key created here is the PowerVS key Terraform will import.

cloud shell or workstation 
# Manage, Access (IAM), API keys
export IC_API_KEY="<paste the API key>"
# -N "" means no passphrase; PowerVS requires RSA
ssh-keygen -t rsa -b 4096 -f ~/.ssh/pvs-lab -N ""
# us-south pairs with PowerVS zone dal12
ibmcloud login --apikey "$IC_API_KEY" -r us-south
# must start with ssh-rsa; Terraform reads this file
cat ~/.ssh/pvs-lab.pub
Expect
Login succeeds for the lab account. The public key starts with ssh-rsa. Terraform reads that file from ~/.ssh/pvs-lab.pub. Keep this shell open so IC_API_KEY stays set.
Overview
API key
Created under Manage, Access (IAM), API keys. IC_API_KEY holds it in this shell. Terraform and ibmcloud login both read that variable.
PowerVS SSH key
An RSA key pair at ~/.ssh/pvs-lab. PowerVS imports a public key that starts with ssh-rsa. Terraform reads the .pub file. Later you log in to AIX as root with the private file.
3

Create the workspace, networks, and SSH key

20–50 · 30 min
Terraform

First plan and apply, still in this shell. aix_image_name stays empty, so the AIX server stays out of this plan. This plan creates the private network and the public network. The server joins both on the next apply. Terraform reads ~/.ssh/pvs-lab.pub. Leave vpc_name empty unless this apply is attaching an existing VPC. Read workspace.tf while the workspace comes up.

cloud shell or workstation 
# lab stack
cd ~/tz-lab-terraform-demo/lab/terraform
# local file, gitignored
cp terraform.tfvars.example terraform.tfvars
# leave vpc_name unset and aix_image_name empty
# the PowerVS key is read from ~/.ssh/pvs-lab.pub

# download the IBM provider
terraform init
# save the workspace, networks, and key
terraform plan -out default.tfplan
# create what the plan saved; prints workspace_crn
terraform apply default.tfplan
Expect
The plan adds the PowerVS workspace, private network, public network, and PowerVS SSH key. When vpc_name is set, it also adds the transit gateway, both connections, and a delegate route. Apply prints workspace_crn.
Overview
PowerVS workspace
The container for this lab's network, SSH key, images, and servers. The zone is dal12, which pairs with region us-south. Apply prints workspace_crn, the id later commands target.
Private network
The workspace network 192.168.100.0/24. The AIX server takes an address on it at the next apply. Cloud Shell and a workstation cannot reach this address.
Public network
A pub-vlan network on the workspace. IBM assigns the public address when the AIX server is created. SSH, ping, and Ansible use aix_public_ip.
Transit gateway
Created when vpc_name is set. It connects the workspace to that VPC and adds a delegate route for the PowerVS CIDR.

What init, plan, and apply do

init Download the IBM provider and the modules for this directory.
→
plan -out Save the workspace, private network, public network, and SSH key in default.tfplan. When vpc_name is set, also save the transit gateway.
→
apply Create the resources saved in default.tfplan and record workspace_crn.
4

Create the AIX virtual server

50–75 · 25 min
IBM Cloud CLI Terraform

Target the new workspace, copy an AIX image name, and apply again. Read instance.tf while the server provisions.

cloud shell or workstation 
# only if this shell is no longer logged in
ibmcloud login --apikey "$IC_API_KEY" -r us-south
# still in ~/tz-lab-terraform-demo/lab/terraform
# catalog commands need a targeted workspace
ibmcloud pi workspace target $(terraform output --raw workspace_crn)
# copy an AIX 7.3 image name
ibmcloud pi image list-catalog

# lab/terraform/terraform.tfvars
# was empty on the first apply
aix_image_name = "<name from image list-catalog>"

# adds the image copy and the AIX server
terraform plan -out default.tfplan
# system type s122
terraform apply default.tfplan
# public address Cloud Shell and this workstation can reach
terraform output -raw aix_public_ip
Expect
The catalog lists stock images. The plan adds the image copy and the AIX server on system type s122, attached to the public network and the private network. A server created before the public network is replaced, so the new server boots with the public address configured. Apply adds a route on this server for the PowerVS CIDR through the subnet gateway when vpc_name is set, and prints aix_public_ip.
Overview
PowerVS plugin
The power-iaas plugin adds the ibmcloud pi commands. workspace target points them at the workspace from the last apply, which image list-catalog needs. Install it with ibmcloud plugin install power-iaas -f when ibmcloud pi is not a command yet.
Stock image
image list-catalog lists the AIX images IBM provides. Copy a 7.3 name into aix_image_name. The next apply copies that image into the workspace.
AIX virtual server
A shared-processor LPAR on system type s122, with 4 GiB of memory. It has a private address and a public address. SSH from this shell uses aix_public_ip.
5

Confirm the workspace and the server

75–90 · 15 min
IBM Cloud CLI Ansible

Start in ~/tz-lab-terraform-demo/lab/terraform. Ping the public AIX address, then run the playbook from this shell. It logs in as root with the PowerVS key. After it finishes, SSH in the same way. The first connection asks you to trust the host key. Answer yes.

cloud shell or workstation 
# CRN should match workspace_crn
ibmcloud pi workspace context
# the AIX server
ibmcloud pi instance list
# the key created in this shell
ibmcloud pi ssh-key list

# public address printed in the last step
aix_ip=$(terraform output -raw aix_public_ip)
# 3 sent, 3 received
ping -c3 -q "$aix_ip"

# playbook directory
cd ~/tz-lab-terraform-demo/lab/ansible
# trailing comma makes a one-host inventory; oslevel, then ping back
ansible-playbook playbook.yml -i "$aix_ip,"

# trust the host key with yes; banner is AIX 7.3
ssh -i ~/.ssh/pvs-lab root@"$aix_ip"
Expect
The context CRN matches workspace_crn. The instance list shows the AIX server. The SSH key list shows the key created in this shell. Ping reports 3 packets transmitted and 3 received. The playbook retries until port 22 answers, oslevel -s prints an AIX level, and the ping from AIX back to this server gets a reply. SSH prints Welcome to AIX Version 7.3! and the prompt is root.
Overview
Ansible
ansible-playbook logs in as root with ~/.ssh/pvs-lab. The trailing comma is a one-host inventory. The play waits until port 22 answers, runs oslevel -s, and pings back to this machine.
AIX SSH
The same key and user, aimed at aix_public_ip. The first connection asks you to trust the host key. The banner is AIX 7.3 and the prompt is root.
